🏷️ Custom Nameplates

Four display systems in a single config file — Nametags above players' heads, Chat Bubbles that float when someone types, Boss Bars at the top of the screen, and an Action Bar message above the hotbar. All support MiniMessage colors, PlaceholderAPI, and a powerful condition system to show different content to different players.

What does it do?

🏷️

Nametags

Custom text lines floating above player heads using TextDisplay entities. Stack multiple lines, each with its own y-offset and conditions.

💬

Chat Bubbles

When a player sends a chat message, a floating text bubble appears above their head. Fades in, stays, then fades out.

📊

Boss Bars

Multiple boss bars shown at the top of the screen. Each bar has its own conditions so different players see different bars.

⚡

Action Bar

Priority-based text above the hotbar. Rotating carousel support — multiple lines cycle automatically.

Requires Paper 1.21+

Nametags and Chat Bubbles use TextDisplay entities which were added in Minecraft 1.19.4. The plugin targets Paper 1.21. Folia is also supported.

File Location

There is only one config file for all four systems:

plugins/
  OreoEssentials/
    custom-nameplates/
      config.yml    ← Everything is here

The file is created automatically with defaults the first time the server starts. To apply changes, either restart the server or run /cnp reload.

Quick Start (5 Minutes)

1

Start the server

The default config is created at plugins/OreoEssentials/custom-nameplates/config.yml with two nametag layers (player name + LuckPerms prefix), chat bubbles, a welcome boss bar, and an action bar already set up. You don't need to do anything — it works immediately.

2

Edit the config to your liking

Open plugins/OreoEssentials/custom-nameplates/config.yml in a text editor. Change the nametag text, the boss bar message, etc. See all options explained below.

3

Reload without restarting

Run /cnp reload in-game or in console. All four systems restart with the new config. Changes are live in seconds.

4

Toggle your own nametag

Players can run /nametag toggle to hide their nametag from others (vanish-style). Admins can run /nametag toggle <player> to toggle anyone.

5

Set a custom bubble color

Players can run /bubblecolor red or /bubblecolor gradient:gold:yellow to set a personal color for their chat bubbles. Run /bubblecolor reset to go back to server default.

Nametags — Global Settings

These settings at the top of the nametag: section control how the whole nametag system behaves. You normally won't need to change the technical ones, but they're explained here so you understand what they do. 

nametag:
  enabled: true
    # true = nametags work. false = turns off nametags completely.

  update-interval-ticks: 100
    # How often (in server ticks) the nametag TEXT is refreshed.
    # 20 ticks = 1 second. 100 ticks = 5 seconds.
    # Lower = more responsive placeholders, higher = less server work.
    # Recommended: 40–100 ticks. Don't go below 10.

  position-interval-ticks: 2
    # How often the TextDisplay ENTITY follows the player's movement.
    # 2 ticks = every 100ms = very smooth. Higher = slightly laggy movement.
    # Recommended: 1–3 ticks.

  visibility-sweep-batch-owners: 8
    # How many players' nametag visibility is rechecked per update cycle.
    # Higher = faster response but more work per tick.
    # Recommended: 4–16 depending on player count.

  move-visibility-cooldown-ticks: 5
    # Minimum ticks between visibility recalculations triggered by movement.
    # Prevents spam-recalculating when many players move at once.
    # Recommended: 3–10 ticks.

  show-to-self: true
    # true  = players can see their OWN nametag above their head
    # false = players only see other players' nametags (more common)

  view-range: 48.0
    # Max distance in blocks at which a nametag is visible.
    # 48 blocks = about 3 chunk edges. Use 32 for less visibility, 64 for more.

Nametag Layers — Multiple Lines Above the Head

A layer is one line of text floating above a player's head. You can have as many layers as you want — each at a different height. Think of them as rows of a custom nameplate.

Layers are defined under nametag.layers. Each key is a name you choose (it doesn't appear in-game, it's just for you to identify them).

Default Example — Two Layers

nametag:
  layers:

    name:                        # You can call this anything
      text: "<white>%player_name%</white>"
      y-offset: 2.1               # Just above the head
      shadow: false
      see-through: false
      background: transparent
      alignment: CENTER
      line-width: 200
      owner-conditions: []
      viewer-conditions: []

    rank:                         # Second layer — HIGHER than the name
      text: "%luckperms_prefix%"
      y-offset: 2.5               # 0.4 blocks higher than the name layer
      shadow: false
      see-through: false
      background: transparent
      alignment: CENTER
      line-width: 200
      owner-conditions: []
      viewer-conditions: []
Layer Ordering

Layers are ordered by y-offset. Higher y-offset = higher above the head. The player's head is at about y-offset 1.8–2.0. Use 2.1 for the name, 2.5 for the rank above it, 2.9 for a guild tag above that, etc.

Three-Layer Example

layers:
  name:
    text: "<white>%player_name%</white>"
    y-offset: 2.1
    background: transparent
    alignment: CENTER
    line-width: 200
    shadow: false
    see-through: false
    owner-conditions: []
    viewer-conditions: []

  rank:
    text: "%luckperms_prefix%"
    y-offset: 2.5
    background: transparent
    alignment: CENTER
    line-width: 200

    see-through: false

    viewer-conditions: []

  guild:

    y-offset: 2.9
    background: transparent
    alignment: CENTER
    line-width: 200
    shadow: false
    see-through: false
    owner-conditions: []
    viewer-conditions: []

Layer Properties — Explained

PropertyTypeExplanation
text string The text shown for this layer. Supports MiniMessage (e.g. <red>text</red>), PlaceholderAPI (e.g. %player_name%), and legacy &a color codes. All color formats are auto-translated.
y-offset number How many blocks above the player's feet this layer is placed. The player's head is at ~1.8–2.0. Use 2.1 for a nameplate, 2.5 for a line above that, etc. Decimals allowed (e.g. 2.35).
shadow true/false true adds a drop shadow behind each character (like in chat). Looks cleaner against busy backgrounds. Default: false.
see-through true/false true makes the text visible even through walls and blocks. Useful for spectator/staff modes. Default: false.
background string Background panel behind the text:
transparent — no background at all (most common for nameplates)
default — the vanilla dark grey panel
#AARRGGBB — custom color with alpha. AA = opacity hex (00=invisible, FF=solid), RRGGBB = color.
Example: #80FF0000 = 50% transparent red.
alignment string Text alignment within the line: CENTER, LEFT, or RIGHT. CENTER looks best for nameplates.
line-width number Maximum pixel width before text wraps to a new line. 200 = default Minecraft chat width. Increase for longer prefixes. 0 = no wrapping.
owner-conditions list Conditions about the player whose head this nametag is on. If any condition fails, this layer doesn't exist at all (not spawned). [] = no conditions = always show.
viewer-conditions list Conditions about the player looking at the nametag. If any condition fails, that specific viewer can't see this layer. [] = everyone can see it.

Background Color Examples

background: transparent     # Fully see-through (recommended for nameplates)
background: default          # Vanilla dark-grey panel
background: "#60000000"      # 37% opaque black (subtle dark panel)
background: "#80FF0000"      # 50% opaque red (for a "danger" effect)
background: "#FF1a1a2e"      # Fully opaque dark navy
ARGB vs RGBA

The format is #AARRGGBB (Alpha first, then Red, Green, Blue). This is different from CSS which uses #RRGGBBAA. Don't mix them up! AA=00 = fully transparent, AA=FF = fully opaque.

The Conditions System

Conditions are rules that must all be true for something to show. You can use them on nametag layers, chat bubbles, boss bars, and action bar entries.

There are two places conditions can go on a nametag layer:

  • owner-conditions — Checks the player who owns the nametag. Example: "only show this layer if the player is in survival mode"
  • viewer-conditions — Checks the player who is looking at the nametag. Example: "only staff can see this layer"
All conditions are AND logic

If you list multiple conditions, ALL of them must be true. There is no built-in OR logic — to achieve OR, create two separate layers with different conditions.

negate: true

Add negate: true to any condition to flip it. For example: "show ONLY if the player does NOT have this permission".

All Condition Types

PERMISSION — Player has a permission

- type: PERMISSION
  value: oreo.staff
    # True if the player has the node "oreo.staff".
    # negate: true → True if the player does NOT have it.

GAMEMODE — Player is in a specific game mode

- type: GAMEMODE
  value: SURVIVAL
    # Valid values: SURVIVAL, CREATIVE, ADVENTURE, SPECTATOR

WORLD — Player is in a specific world

- type: WORLD
  value: survie
    # Use the exact world folder name. Case-insensitive.

REGION — Player is inside a WorldGuard region

- type: REGION
  value: spawn
    # Requires WorldGuard plugin. Use the region name exactly.

PAPI_EQUALS — Placeholder output equals a value

- type: PAPI_EQUALS
  placeholder: "%luckperms_primary_group%"
  value: "admin"
    # True if the placeholder output exactly equals "admin" (case-insensitive).
    # Requires PlaceholderAPI.

PAPI_CONTAINS — Placeholder output contains a substring

- type: PAPI_CONTAINS
  placeholder: "%luckperms_prefix%"
  value: "VIP"
    # True if the prefix contains the text "VIP" anywhere in it.

PAPI_GREATER — Placeholder number is greater than a value

- type: PAPI_GREATER
  placeholder: "%player_level%"
  value: "30"
    # True if %player_level% is greater than 30.
    # The placeholder output must be a number (integer or decimal).

PAPI_LESS — Placeholder number is less than a value

- type: PAPI_LESS
  placeholder: "%player_level%"
  value: "10"
    # True if %player_level% is less than 10.
    # Great for "beginner" states.

Condition Examples — Real Scenarios

Show a layer only to staff members (viewer must be staff)

viewer-conditions:
  - type: PERMISSION
    value: oreo.staff
  # Only players with oreo.staff see this layer — useful for a "real UUID" debug layer.

Only show a layer when the owner (tagged player) is in survival

owner-conditions:
  - type: GAMEMODE
    value: SURVIVAL
  # Layer disappears when owner enters creative/spectator mode.

Show a VIP tag only for VIP players

owner-conditions:
  - type: PERMISSION
    value: oreo.vip
  # The layer only exists if the owner has oreo.vip.

Show a layer only in a specific world AND only to admins

owner-conditions:
  - type: WORLD
    value: pvp_world
viewer-conditions:
  - type: PERMISSION
    value: oreo.admin
  # Owner must be in pvp_world AND viewer must be admin.

Show a layer to everyone EXCEPT players with a permission (negate)

viewer-conditions:
  - type: PERMISSION
    value: oreo.nametag.hide
    negate: true
  # Everyone sees this layer UNLESS they have oreo.nametag.hide.

Show a "High Balance" tag to players with over 10,000 money

owner-conditions:
  - type: PAPI_GREATER
    placeholder: "%vault_eco_balance%"
    value: "10000"
  # Layer only appears if the player's Vault balance is over 10,000.

Show a layer only inside a WorldGuard spawn region

owner-conditions:
  - type: REGION
    value: spawn
  # Requires WorldGuard. The region name must match exactly.

Chat Bubbles — Overview

When a player types in chat, a text bubble floats above their head showing what they said. It fades in, stays visible for a bit, then fades out. Other players nearby can see it.

The system uses a TextDisplay entity just like nametags. Opacity is animated using the entity's transformation/brightness API. You can control exactly how long it takes to appear, how long it stays, and how long it takes to disappear.

Chat Bubbles — All Settings Explained

chat-bubbles:
  enabled: true
    # true = chat bubbles work. false = no bubbles at all.

  y-offset: 2.6
    # Height above the player's feet where the bubble appears.
    # 2.6 = just above the head's highest point. Increase to push it higher.

  view-range: 32.0
    # Max distance in blocks at which nearby players can see the bubble.
    # 32 blocks = 2 chunks. 16 is tighter, 48 is wider.

  stay-duration: 80
    # Ticks the bubble stays fully visible BEFORE fading out.
    # 80 ticks = 4 seconds. 200 ticks = 10 seconds.

  appear-duration: 5
    # Ticks for the fade-IN animation (opacity 0 → full).
    # 5 ticks = 0.25 seconds. Use 1 for instant, or 10–20 for a slower pop-in.

  disappear-duration: 10
    # Ticks for the fade-OUT animation (opacity full → 0).
    # 10 ticks = 0.5 seconds. Use 20–30 for a longer, smoother fade.

  max-lines: 3
    # If a message is too long and wraps, it is truncated to this many lines.
    # Set to 1 for single-line only, 5 for more generous bubbles.

  line-width: 160
    # Pixel width before text wraps to the next line.
    # 160 is a bit narrower than chat (200). Use 120 for tighter bubbles.

  shadow: false
    # true = text has a drop shadow. false = clean text.

  see-through: false
    # true = bubble visible through walls. Normally keep this false.

  background: transparent
    # transparent | default | #AARRGGBB — same as nametag background.

  text-prefix: ""
    # MiniMessage text added BEFORE every bubble message.
    # Example: "<dark_gray>💬 " will add a speech bubble icon.

  text-suffix: ""
    # MiniMessage text added AFTER every bubble message.

  sender-conditions: []
    # Conditions on the SENDER. If these fail, their message creates no bubble.
    # Example: restrict to survival mode only.

  viewer-conditions: []
    # Conditions on the VIEWER. If these fail, that player doesn't see any bubble.

Example — Compact, Quick Bubbles

chat-bubbles:
  enabled: true
  y-offset: 2.7
  view-range: 20.0
  stay-duration: 60
  appear-duration: 3
  disappear-duration: 8
  max-lines: 2
  line-width: 140
  shadow: false
  see-through: false
  background: transparent
  text-prefix: "<dark_gray>💬 "
  text-suffix: ""
  sender-conditions: []
  viewer-conditions: []

Chat Bubbles — Background Icon

You can add a custom graphic behind each chat bubble — a separate TextDisplay entity containing a custom font glyph. This is mainly used with ItemsAdder or Nexo to show a speech bubble panel or other decorative image. 

  background-icon:
    enabled: false
      # Set to true to enable the background entity.

    text: ''
      # The MiniMessage string for the background. Usually a <font:> glyph.
      # ItemsAdder example: '<font:default>\uE001</font>'
      # Nexo example:       '<font:nexo:your_namespace>\uE001</font>'
      # The \uE001 is the unicode character — find it in your resource pack.

    scale: 1.0
      # Entity scale multiplier. 1.0 = normal size. 1.5 = 50% bigger. 0.8 = 80%.
      # Increase this if the glyph is too small relative to the text bubble.

    offset-x: 0.0
      # Horizontal offset in blocks (0 = centered on player, positive = shift right).

    offset-y: 0.0
      # Extra vertical offset ON TOP of y-offset. 0.0 = same height as text bubble.
      # Negative values push it lower, positive push it higher.
How the background renders behind the text

The background icon entity is spawned first (lower entity ID) so the game renders it behind the text bubble. It fades in and out at the same speed as the text bubble. If your glyph is clipping over the text, try increasing offset-y slightly or decreasing scale.

Finding the unicode character in ItemsAdder

Open your ItemsAdder resource pack → assets/minecraft/font/default.json (or your custom namespace). Find your image entry. The chars field contains the unicode character to use. Copy that character and paste it as the text value.

Boss Bars — Overview

Boss bars are the colored bars at the top of the screen. OreoEssentials lets you define multiple boss bars, each shown only to players who meet specific conditions. Each bar can rotate through multiple texts (carousel) automatically. 

bossbars:
  enabled: true
    # true = boss bars enabled. false = none shown.

  refresh-interval-ticks: 40
    # How often conditions and text are re-evaluated for every player.
    # 40 ticks = 2 seconds. Lower = more responsive but more server work.
    # Recommended: 20–60 ticks.

  bars:
      # Each key here is a bar you define — name them whatever you want.

Boss Bars — Bar Settings

Each bar under bossbars.bars has these properties:

PropertyTypeDescription
texts list One or more MiniMessage strings. If there's more than one, they rotate. PlaceholderAPI is supported.
carousel-interval-ticks number How many ticks between text rotations. Ignored if there's only one text. 100 ticks = 5 seconds between each text.
color string Bar color: BLUE, GREEN, PINK, PURPLE, RED, WHITE, YELLOW
style string Visual style: SOLID (one continuous bar), SEGMENTED_6, SEGMENTED_10, SEGMENTED_12, SEGMENTED_20 (divided into notches)
progress 0.0 – 1.0 How full the bar is. 1.0 = completely full, 0.5 = half full, 0.0 = empty.
conditions list Conditions the player must meet to see this bar. [] = show to everyone. Uses the same condition format as nametags.

Default Example Bars

  bars:
    welcome:
      texts:
        - "<gradient:#ff6b6b:#ffd93d>Welcome to the server!</gradient>"
        - "<gray>Type /help for a list of commands"
      carousel-interval-ticks: 100    # Switch every 5 seconds
      color: PURPLE
      style: SOLID
      progress: 1.0
      conditions: []               # Show to everyone

    staff-bar:
      texts:
        - "<red>⚑ Staff Mode Active"
      carousel-interval-ticks: 60
      color: RED
      style: SEGMENTED_10
      progress: 1.0
      conditions:

Action Bar — Overview

The action bar is the line of text just above the player's hotbar. OreoEssentials replaces it with a priority-based, multi-entry system:

  • You define multiple entries, each with a priority number
  • On every refresh, the system checks each entry in priority order (highest first)
  • The first entry whose conditions all pass is displayed — others are skipped
  • Each entry can have multiple texts that rotate automatically (carousel)

Action Bar — Entries & Priority

actionbar:
  enabled: true
    # true = custom action bar is sent. false = no action bar from this plugin.

  refresh-interval-ticks: 20
    # How often the action bar is re-evaluated and resent to each player.
    # 20 ticks = once per second. Minecraft clears the action bar after ~60 ticks
    # of no update, so don't go above 40–50 ticks unless you want flickering.

  entries:
      # Each entry is a named block. The name is just for you — it doesn't appear in-game.

    info:                                 # Just a label
      priority: 10                         # Higher number = checked first
      texts:
        - "<gray>❤ <red>%player_health%</red>  ✦ <gold>%player_level%</gold>"
        - "<gray>⚡ <yellow>%player_ping%ms</yellow>"
      carousel-interval-ticks: 60          # Switch text every 3 seconds
      conditions: []                       # Show to everyone
Priority Logic

Entries are sorted by priority and evaluated top-down. The first one whose conditions pass is shown. So if you have a "combat" entry with priority 50 and a "default info" entry with priority 10, and a player is in combat, they'll see the combat bar instead of the info bar. As soon as they leave combat, the conditions fail and they fall through to the info bar.

Performance Tips

  • Increase update-interval-ticks — If you have many players online, set this to 60–100 ticks. The text refresh runs less often but the plugin does less work per second.
  • Reduce visibility-sweep-batch-owners — Lower this if you notice lag spikes. It spreads the visibility work across more ticks rather than doing it all at once.
  • Use transparent background on nametags — The default background creates a grey panel that's drawn for every viewer. transparent skips this rendering step.
  • Reduce view-range — A smaller view range means fewer players need to track each other's nametag entities. 32 blocks is usually enough; 64+ is heavy on large servers.
  • Limit PlaceholderAPI calls in fast entries — Action bar has a refresh-interval-ticks of 20 by default (once per second). If your placeholders are slow to resolve, bump this to 40.
  • Disable unused features — If you don't use chat bubbles, set chat-bubbles.enabled: false. Each disabled feature is zero overhead.

FAQ / Troubleshooting

Q: Nametags don't appear at all.

Check these in order:

  1. Is nametag.enabled: true in the config?
  2. Do you have at least one entry under nametag.layers?
  3. Check the server console for any [Nametag] error messages during startup.
  4. If you're testing on yourself, make sure show-to-self: true or look at another player.
  5. Run /cnp reload and check the console for "Nametag] TextDisplay nametags enabled (X layer(s))."

Q: Nametags are showing but the text is wrong / placeholders aren't working.

  • Make sure PlaceholderAPI is installed if you're using %placeholder% syntax.
  • Make sure the specific expansion is installed. For %luckperms_prefix%, you need the LuckPerms expansion (/papi ecloud download LuckPerms).
  • Check the placeholder name — most are lowercase and use underscores.

Q: I changed the config but nothing updated in-game.

You need to reload: run /cnp reload. The config is not watched automatically.

Q: The LuckPerms prefix has weird & codes instead of colors.

This is handled automatically — the plugin translates &a, &6, &#RRGGBB, and Spigot hex codes to MiniMessage format before rendering. If you still see raw codes, make sure the text is going through the nametag system and not being intercepted by another plugin.

Q: Chat bubbles show for everyone, but I want to restrict them to a certain world.

  sender-conditions:
    - type: WORLD
      value: survie
  # Only players in the "survie" world will create bubbles.

Q: I want a nametag layer that's only visible to the player looking at someone in creative mode.

viewer-conditions:
  - type: GAMEMODE
    value: CREATIVE
  # Only viewers in creative mode can see this layer.

Q: Can I have conditions on boss bars that use PlaceholderAPI?

Yes! Boss bar conditions use the exact same system as nametag conditions. All condition types including PAPI_EQUALS, PAPI_GREATER, etc. work for boss bars.

Q: After toggling my nametag off with /nametag toggle, it still shows. Why?

The toggle state is stored in memory only. If the server restarts or /cnp reload is run, the toggle resets. The toggle state is not persisted to disk between restarts.

Q: Can two boss bars be shown at the same time?

Yes! Unlike the action bar (which only shows the highest-priority match), all boss bars whose conditions pass are shown simultaneously. A player can see multiple boss bars at once if they meet the conditions for multiple bars.

Q: The background icon for chat bubbles is showing in front of the text, not behind.

The rendering order depends on entity spawn order — the background icon must spawn first. This is handled automatically. If you're still seeing it in front, try reducing scale slightly or adjusting offset-y so it sits further behind.
