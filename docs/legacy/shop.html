Shop Module

A full GUI shop system â€” players buy and sell items, admins control prices, economy uses Vault or custom currencies (tokens), with dynamic pricing that reacts to player demand.

The shop module gives your server a clean, icon-based store. Players open it with /shop, browse categories, click items to buy or sell, and use an amount-selection screen to pick exactly how many they want. As an admin, you can set up as many shops as you like, wire them up to different currencies, and let prices drift with demand automatically.

Where are the files? All shop config lives in plugins/OreoEssentials/shop/. The main settings are in config.yml, text messages in messages.yml, and each shop is a separate YAML file inside the shops/ sub-folder.

15 Built-in Shops

Ores, weapons, armor, tools, food, potions, enchanted books, building blocks, farming, nether, redstone, mob drops, end items, token shop, and a daily rotating shop â€” all pre-configured.

Dual Economy

Each shop can use Vault (server money) or a custom currency (e.g. tokens). The token shop is a separate store where everything costs tokens instead of coins.

Dynamic Pricing

When players buy a lot of an item, its price goes up automatically. When nobody buys it for a while, the price drifts back down. This prevents market flooding.

Price Modifiers

Admins can give individual players discounts or markups â€” globally, per-shop, or per-item. Great for VIP ranks or punishments.

Daily Rotation

A special shop shows only 4 random items from a pool each day. The selection resets at midnight (configurable). Creates excitement and trading opportunities.

Anti-Dupe Protection

Built-in cooldowns, rate limits, transaction locking, and an auto-kick system for suspicious activity prevent item or money duplication exploits.

Quick Start

Get the shop working in under 5 minutes:

Install Vault and an economy plugin (e.g. EssentialsX, CMI, or any Vault-compatible economy). The shop needs Vault to handle money unless you're using only custom currencies.

Restart your server. OreoEssentials will automatically create the plugins/OreoEssentials/shop/ folder with all default files â€” 15 shop YAMLs, config.yml, and messages.yml.

Give players the oshopgui.shop permission (or put it in your default group). Without this they can't open the shop at all.

Give players sell permissions: oshopgui.sell.hand, oshopgui.sell.hand.all, oshopgui.sell.all â€” or all three at once.

Test in-game: type /shop to open the main menu. Click any category icon to browse items. Left-click an item to buy, right-click to sell.

Customize prices by editing the files in plugins/OreoEssentials/shop/shops/, then run /shop reload in-game to apply changes instantly.

No Vault installed? The shop will still work for shops that use a custom currency (like the token shop), but money-based shops will show errors. Always install Vault + an economy plugin for a full experience.

Controls whether the shop is on, which language to use, anti-dupe safety, and how the main menu looks.

Anti-Dupe Protection

These settings stop players from exploiting the shop to duplicate items or money.

anti-dupe:
  enabled: true                   # Master switch for anti-dupe
  cooldown-ms: 500               # Minimum milliseconds between transactions (500 = 0.5 seconds)
  verify-inventory: true         # Double-check player has items before selling
  log-suspicious: true           # Log suspicious activity to console/file
  max-transactions-per-second: 5 # Rate limit: more than 5 transactions/sec = suspicious
  lock-during-transaction: true  # Prevent a player from opening two transactions at once
How the rate limit works: The plugin tracks timestamps of the last transactions. If a player completes more than max-transactions-per-second transactions in a rolling 1-second window, a "flag" is recorded. At 10 flags the player is automatically kicked. Flags reset on disconnect.

Item Format â€” How to Define Shop Items

Every item in a shop file follows the same YAML structure. Here's every possible field explained.

Full Item Example

items:
  diamond_sword_p1s4:          # Unique ID for this item â€” can be anything, no spaces
    material: DIAMOND_SWORD      # Bukkit material name (must be ALL_CAPS)
    name: "&bDiamond Sword"      # Optional custom display name. Leave out to use default.
    lore:                        # Optional tooltip lines
      - "&7A sharp blade"
      - "&7Made of diamond"
    slot: 4                       # Slot position (0 = top-left). Bottom row = navigation bar!
    page: 1                       # Which page this item appears on
    amount: 1                     # How many items per "unit" (e.g. 64 = sell by the stack)

Item ID Naming Convention

The ID format used in default shops is materialname_pPAGEsSLOT â€” for example diamond_sword_p1s4 means Diamond Sword, page 1, slot 4. This is just a convention to keep IDs unique and readable; you can use any ID you like as long as there are no duplicates within the same shop.

Dynamic Pricing â€” Demand-Based Prices

Prices automatically rise when an item is bought often, and fall back when demand drops. This makes the economy feel alive.

Enable it in config.yml with dynamic-pricing.enabled: true. Once enabled, every time a player buys an item, an internal buy-count increments. This count drives a "pressure" value between 0.0 and 1.0.

Buy Price Formula

price Ã— (1 + pressure Ã— (maxMult âˆ’ 1))
With default settings: at max pressure a $1,000 item costs $3,000.

Sell Price Formula

price Ã— max(1 âˆ’ pressure Ã— (1 âˆ’ minMult), minMult)
At max demand you only get 20% of the base sell price.

Pressure Decay

Every decay-interval-minutes (default 60min), each item's pressure is reduced by 5% of its current value. Low-demand items slowly return to base price.

How Pressure Is Calculated

# pressure = min(buy_count / demand_scale, 1.0)
# Example: 250 purchases of diamond, demand_scale=500
# pressure = 250/500 = 0.5  (50% of max pressure)
# Buy multiplier  = 1 + 0.5 Ã— (3.0 - 1) = 2.0  â†’ diamond costs 2Ã— base price
# Sell multiplier = max(1 - 0.5 Ã— (1 - 0.2), 0.2) = 0.6  â†’ sell for 60% of base

Trend Lore Indicator

With show-trend-in-lore: true, items show a trend arrow in the shop GUI:
â†‘ High demand means buy price is elevated. â†“ Low demand means sell price is better than usual.

Tip: Set demand-scale based on your server size. A small server with 20 players should use a lower value (50â€“100). A large server with 200+ players can go up to 1000+. If demand-scale is too low, prices spike from just a few purchases.

Price Modifiers â€” Per-Player Discounts

Give specific players custom buy/sell prices â€” globally, for a specific shop, or for a specific item.

Price modifiers are applied on top of dynamic pricing. Three levels exist, applied in priority order:

  1. Item modifier â€” highest priority: affects one item in one shop for one player
  2. Shop modifier â€” affects all items in one specific shop for one player
  3. Global modifier â€” lowest priority: affects all shops for one player

Modifier values are percentages. 100 = normal price. 90 = 10% discount. 110 = 10% markup.

Commands

CommandDescriptionExample
/shop addmodifier global <player> <value> [buy|sell] Set a global buy or sell modifier for a player /shop addmodifier global Steve 90 buy â†’ Steve gets 10% off all buys
/shop addmodifier shop <player> <shop> <value> [buy|sell] Set a modifier for one shop /shop addmodifier shop Alex ores_minerals 80 sell â†’ Alex sells ores for 20% less
/shop addmodifier item <player> <shop> <item> <value> [buy|sell] Set a modifier for one specific item /shop addmodifier item Notch enchanted_books mending_1s35 50 buy â†’ Notch buys Mending at 50% off
/shop resetmodifier global <player> Remove global modifier from player /shop resetmodifier global Steve
/shop resetmodifier shop <player> <shop> Remove shop modifier from player /shop resetmodifier shop Alex ores_minerals
/shop resetmodifier item <player> <shop> <item> Remove item modifier from player
/shop checkmodifiers <player> Show all active modifiers for a player /shop checkmodifiers Steve
Note: Modifiers are stored in memory and reset when the server restarts. They are intended for temporary discounts (sales events, VIP bonuses during a session). For permanent discounts, consider setting per-item prices in the shop YAML.

Daily Rotation Shop

A special shop that shows only a random subset of its item pool each day â€” creating scarcity and excitement.

The rotating shop is defined in shops/daily_rotating_shop.yml. By default, 4 items are randomly chosen from a pool of 8 each day at midnight. The selection is saved to disk so a server restart doesn't change today's rotation.

Rotation Configuration

shop-id: daily_shop

rotating:
  enabled: true              # Must be true for rotation to work
  display-count: 4          # How many items to show from the pool each day
  reset-time: "00:00"       # Time of day when the rotation resets (24-hour HH:mm format)
  timezone: "Europe/Paris"  # IANA timezone ID. See https://en.wikipedia.org/wiki/List_of_tz_database_time_zones

items:                       # ALL items in the pool (8 defined, only 4 shown per day)
  diamond_sword:
    material: DIAMOND_SWORD
    slot: 0
    page: 1
    amount: 1
    buy-price: 120000
    sell-price: -1
  # ... more items in pool ...

How the Rotation Works

When the shop is first opened after the reset time, it checks if the saved rotation has expired.

If expired (or no rotation saved), it shuffles all items in the pool using a Fisher-Yates algorithm and picks the first display-count items.

The chosen item IDs are saved to disk so the selection persists across restarts.

The next reset time is computed: if the configured reset time has already passed today, the next reset is tomorrow at that time.

Admin Force-Reroll

Admins can immediately reroll the daily shop with:

/shop reroll daily_shop   # Forces a new random selection right now
Timezone matters! Make sure the timezone field matches your server's expected reset timezone. If left blank or wrong, the reset time may be off by hours. Use a standard IANA zone like Europe/Paris, America/New_York, or UTC.

Anti-Dupe Protection

Multiple layers of protection prevent item and money duplication exploits.

Transaction Lock

While a player's transaction is processing, a lock prevents them from starting another. This stops double-click or lag exploits from triggering two purchases at once.

Cooldown

After each transaction, a configurable cooldown (default 500ms) blocks any new transaction. Prevents rapid-fire clicking from triggering dozens of purchases.

Rate Limiting

Tracks transaction timestamps in a 1-second window. More than max-transactions-per-second transactions in 1 second increments a flag counter. At 10 flags â†’ auto-kick.

Inventory Verify

Before accepting a sell, the plugin counts the player's actual inventory to confirm they have enough items. Prevents selling items they no longer have due to lag.

Space Verify (Buy)

Before a buy, confirms the player's inventory has room. If not, the buy is rejected and money is not charged â€” prevents losing money to a full inventory.

Auto-Cleanup

When a player disconnects or is kicked, all their locks, cooldowns, and rate-limit data are cleared. No stuck state remains after a player leaves.

Custom currency sell order: When selling with a custom currency (tokens), items are only removed from the player's inventory after the deposit succeeds. This means if the currency system is down, the player keeps their items. No money-without-items exploit is possible.

Frequently Asked Questions

Players can't open the shop â€” what's wrong?

Make sure players have the oshopgui.shop permission. Also check that enabled: true is set in config.yml. If using LuckPerms: lp group default permission set oshopgui.shop true.

The shop says "Vault not found" or transactions fail.

You need both Vault (the API plugin) AND an economy plugin (EssentialsX, CMI, etc.) installed. Vault alone is just an API â€” it doesn't provide any economy by itself. Install both, restart, and the error should disappear.

I added an item to a shop YAML but it doesn't appear in-game.

Run /shop reload after editing any shop file. Also check:

  • The page field matches the page you're viewing
  • The slot is within bounds (not in the navigation row)
  • The material name is valid (use ALL_CAPS exactly as Bukkit defines it)
  • If you set a permission field, the player has that permission
Enchanted books in the shop aren't working â€” the enchantment doesn't apply to tools.

This was a bug that has been fixed. When you buy an enchanted book from the shop, the enchantment is now correctly stored inside the book as a stored enchantment. To apply it to a tool, use an anvil. If you're on an older version where this was broken, update to get the fix.

How do I create a new shop?

Create a new file in plugins/OreoEssentials/shop/shops/, e.g. my_custom_shop.yml. Give it a unique shop-id, add items following the item format. Then add a button for it in config.yml under main-menu-items with shop: my_custom_shop. Run /shop reload.

How do I disable buying or selling for a specific item?

Set the price to -1: buy-price: -1 disables buying, sell-price: -1 disables selling. An item with both set to -1 won't appear in the shop at all (no interactable action).

How do I add a second page to a shop?

Set pages: 2 (or however many you need) in the shop header. Then set page: 2 on the items you want on the second page. Make sure those items have slot values within the valid range (0 to rowsÃ—9 - 10, avoiding the navigation bar).

The token shop prices show in $ instead of tokens.

Check that the currency: field in token_shop.yml exactly matches the currency ID you created. Open your currency configuration and verify the ID. Remember: it's case-sensitive and must match exactly (e.g. if you created it as token, the field must say currency: token).

Dynamic pricing is making items too expensive â€” how do I tune it?

Increase demand-scale so it takes more purchases to reach max pressure. For example, if 50 buys are spiking prices, try demand-scale: 500 so prices don't hit maximum until 500 purchases. You can also lower max-buy-multiplier â€” setting it to 1.5 caps the buy price increase at 50% above base instead of 200%.

The daily rotation didn't change at midnight.

Check the timezone in daily_rotating_shop.yml. If your server runs in UTC but you set Europe/Paris, the reset happens at midnight Paris time (1am UTC in winter, 2am in summer). Also confirm that the rotation file is being written correctly â€” check logs/latest.log for any errors from the shop module on startup.

A player is stuck and can't use the shop â€” locked out.

The anti-dupe lock releases automatically when the transaction completes or when the player disconnects. If a player is permanently stuck (very rare edge case), have them reconnect â€” the onQuit event always clears all locks. If they're still stuck after reconnecting, use /shop reload which reinitializes the transaction processor.

Can I have shops accessible only from specific NPCs?

Yes. Open the shop programmatically from your NPC plugin using the command /shop <player> <shopId> via player.performCommand() or dispatch a command. You can also set hide-back-button: true in the shop YAML to hide the "Back to Main Menu" button, making the shop feel self-contained.
