Chat & Messaging

This page covers every part of the OreoEssentials chat system: how a message goes from keypress to screen, the full placeholder list, the channel system, hover cards, the [item] feature, Discord bridge, cross-server sync, moderation, and all four messaging YAML files.

Main config file plugins/OreoEssentials/chat-messaging/chat-format.yml — all chat settings live here.
Two chat modes Channels off → simple per-group format. Channels on → AsyncChatListenerWithChannels handles everything. Only one listener is active at a time.
MiniMessage everywhere All formats are parsed by MiniMessage after PAPI runs on the format string. Legacy & codes are auto-converted when minimessage-translate-legacy-amp: true.

Overview & Config Files

There are four YAML files under plugins/OreoEssentials/chat-messaging/. They cover different concerns.

FileWhat it controls
chat-format.yml Chat format per group, channels, hover cards, [item], Discord bridge, cross-server RabbitMQ
join-quit-messages.yml Join and quit messages, auto broadcast messages, and the Oreobot conversation system
death-messages.yml All PvP and environmental death message templates
events.yml Commands to run automatically when specific server events fire (join, kill, respawn, etc.)

Master switches

# settings.yml — the global kill-switch for the whole chat module
features:
  chat:
    enabled: true

# chat-format.yml — secondary toggle inside the file itself
chat:
  enabled: true

Both must be true for OreoEssentials to intercept any chat event. If features.chat.enabled is false the event is left untouched (other plugins can still handle it).

Message Pipeline

This is exactly what happens from the moment a player presses Enter to the moment the message appears on screen.

Paper AsyncChatEvent (HIGHEST)
→
Mute / slowmode / staff-chat / global mute checks
→
Banned-word censor
→
PlainText extract from Component
→
Switch to sync scheduler thread
→
FormatManager.formatMessage() → returns MiniMessage template
→
Build TagResolver (all placeholders)
→
MiniMessage.deserialize(template, resolver)
→
processItemPlaceholder() if [item] present
→
Attach hover to sender name + mentioned player names
→
Broadcast to all online players
→
RabbitMQ sync (JSON component)
→
Discord webhook (plain text)
Low-priority intercept: a second handler at EventPriority.LOW with ignoreCancelled=false checks whether the player is waiting for AH / Orders GUI input before the HIGHEST handler runs. If so the message is consumed silently and never reaches the chat pipeline.
Channels mode: when chat.channels.enabled: true the pipeline above is replaced by AsyncChatListenerWithChannels and ChatChannelHandler. The format lookup, resolver, item placeholder, hover, and sync steps all still run — the difference is the format comes from the channel definition instead of FormatManager, and messages are only sent to players in the same channel who pass the scope check.

All Placeholders

These MiniMessage tags are injected by the code as a TagResolver before the format string is parsed. They work in both simple mode and channel mode.

PlaceholderTypeValue
<chat_message> parsed / unparsed The player's typed message. Uses Placeholder.parsed() if the player has oreo.chat.colors, otherwise Placeholder.unparsed() (colors stripped).
<lp_prefix> Component LuckPerms prefix, deserialized as legacy or MiniMessage automatically. PAPI is run inside the prefix string itself before deserialization.
<lp_suffix> Component LuckPerms suffix. Same processing as prefix. Available in channel mode only — not injected in simple mode.
<player_name> unparsed Raw Bukkit username. Cannot contain MiniMessage tags.
<player_displayname> unparsed Display name (may differ from username if set).
<server_name>unparsedFrom config.yml server name setting.
<player_world>unparsedBukkit world name the player is in.
<player_x>, <player_y>, <player_z>unparsedCoordinates formatted to 1 decimal place.
<player_ping>unparsedCurrent ping in ms.
<player_health>unparsedCurrent health, rounded up to nearest integer.
<player_max_health>unparsedMax health via attribute API.
<player_level>unparsedXP level.
<player_gamemode>unparsedGame mode name (e.g. SURVIVAL).
<player_uuid>unparsedPlayer UUID string.
<lp_primary_group>unparsedLuckPerms primary group name.
<time_24h>unparsedServer time formatted as HH:mm:ss.
<date>unparsedServer date formatted as yyyy-MM-dd.

PlaceholderAPI

PAPI runs on the format string before the MiniMessage parse step (chat.papi.apply-to-format: true by default). You can use any %papi_placeholder% directly in your format. PAPI is not applied to the player's message content unless you explicitly set chat.papi.apply-to-message: true — keep that false to prevent injection.

How <lp_prefix> is resolved: the code reads meta.getPrefix() from LuckPerms, runs PAPI on it, then tries to deserialize it first as a legacy-section string (§), then legacy-ampersand (&), then plain text. This means your LuckPerms prefix can use any of those three formats.

Simple Chat — Format Resolution

When chat.channels.enabled: false, FormatManager picks a format for each message by looking up the player's LuckPerms primary group.

chat:
  use-minimessage: true                    # false = legacy-only path (rare)
  minimessage-translate-legacy-amp: true   # auto-converts &a, &6, etc. in the format

  papi:
    apply-to-format: true    # run PAPI on the format string (safe)
    apply-to-message: false  # run PAPI on the player's typed message (risky, keep false)

  # Lookup key = player's LP primary group name.
  # If the group key is not found, falls back to "default".
  default: "<lp_prefix><white><player_name></white> <dark_gray>»</dark_gray> <white><chat_message></white>"
  admin:   "<red><bold>[Admin]</bold></red> <lp_prefix><gold><player_name></gold> <dark_gray>»</dark_gray> <white><chat_message></white>"
  vip:     "<gold>[VIP]</gold> <lp_prefix><yellow><player_name></yellow> <dark_gray>»</dark_gray> <white><chat_message></white>"

The lookup code is literally: cfg.getString("chat." + lpPrimaryGroup), then cfg.getString("chat.default", ...hardcoded_fallback...). So any key you add directly under chat: that matches a group name will be used for that group.

Important: FormatManager.formatMessage() returns a MiniMessage template string — not a fully rendered component. The <chat_message> placeholder is left unreplaced inside it. The actual message content is injected later as a TagResolver when MM.deserialize() is called. This is what prevents MiniMessage injection from user input.

Color Permission

The permission oreo.chat.colors controls whether a player can use formatting tags in their own typed messages.

Has oreo.chat.colorsHow <chat_message> is injectedEffect
Yes Placeholder.parsed() MiniMessage tags in the message body are rendered. &a codes are also auto-converted first.
No Placeholder.unparsed() All tags in the message body are escaped and shown literally. Players cannot color their text.
Before injecting the player message for color-permitted players, the code calls FormatManager.convertLegacyToMiniMessage() on the message string — this converts &c, &l, hex &#rrggbb, and §x§r§r§g§g§b§b formats to MiniMessage equivalents.

Channel System — Overview

Enable the channel system with chat.channels.enabled: true. When enabled, every chat message goes through ChatChannelHandler instead of FormatManager. The simple per-group format keys are ignored.

chat:
  channels:
    enabled: true
    default_channel: "global"         # channel new players land in
    remember_last_channel: true       # persist player's channel choice across logins

    cross_server:
      enabled: false                  # true = use MongoDB to persist channel membership across servers

    formatting:
      enabled: true
      fallback_format: "<gray><player_name></gray><dark_gray>: </dark_gray><white><chat_message></white>"

    list_order:
      - "global"
      - "announcements"
      - "trade"
      - "local"
      - "staff"
      - "help"

Channel membership is persisted per-player. Default storage is YAML (plugins/OreoEssentials/channel-data.yml). If cross_server.enabled: true AND a MongoClient is available, membership is stored in MongoDB so players keep their channel when switching servers.

Channel Fields

Each channel is defined under chat.channels.channel_definitions.<id>.

chat:
  channels:
    channel_definitions:

      global:
        enabled: true
        display_name: "<gradient:#FF1493:#00FF7F>Global</gradient>"
        description: "<gray>Server-wide chat</gray>"

        # null = everyone. A permission string = only players with that permission.
        talk_permission: null
        view_permission: null
        join_permission: null   # falls back to talk_permission if null

        scope:
          type: "ALL"
          range_blocks: 0

        formatting:
          enabled: true
          format: "<gray>[G]</gray> <lp_prefix><white><player_name></white><dark_gray>: </dark_gray><white><chat_message></white>"

          rank_formats:
            default: "<gray>[G]</gray> <white><player_name></white><dark_gray>: </dark_gray><white><chat_message></white>"
            vip:     "<gold>[★ G]</gold> <lp_prefix><gold><player_name></gold><dark_gray>: </dark_gray><yellow><chat_message></yellow>"
            admin:   "<red>[⚡ G]</red> <lp_prefix><red><player_name></red><dark_gray>: </dark_gray><white><chat_message></white>"

        join_message: "<gray>You are now chatting in </gray><gradient:#FF1493:#00FF7F>Global</gradient><gray>!</gray>"
        discord_webhook: null
FieldRequiredMeaning
enabledNo (default true)Disable a channel without deleting its config.
display_nameNoMiniMessage string shown in the GUI and messages. Falls back to the channel ID if absent.
descriptionNoShort description shown in the channel GUI.
talk_permissionNonull = everyone. A permission node = read-only for players without it.
view_permissionNoPlayers without this cannot receive messages from the channel.
join_permissionNoControls who can join (switch into) this channel. Falls back to talk_permission if null.
scope.typeYesSee Scopes below.
scope.range_blocksOnly for RANGERadius in blocks for RANGE scope.
formatting.enabledNo (default true)If false, the channel uses the global fallback format.
formatting.formatNoMiniMessage template. Falls back to channels.formatting.fallback_format if absent.
formatting.rank_formatsNoPer LP-group format overrides. See Per-Rank Formats.
join_messageNoSent to the player when they switch into this channel. MiniMessage.
discord_webhookNoPer-channel Discord webhook URL. Overrides the global webhook if set.

Channel Scopes

The scope controls which players receive a message. Only players who are both in the channel AND pass the scope check receive it.

ScopeWho hears itNotes
ALL Every player in this channel on this server Standard global channel.
WORLD Players in the same Bukkit world Compared with player.getWorld().equals(sender.getWorld()).
RANGE Players within range_blocks of the sender, same world Uses Bukkit Location.distance(). Requires scope.range_blocks > 0.
SERVER Every player in this channel on this server Same as ALL locally. The name is semantic — intended for cross-server setups where only this server's players should hear it.
SHARD Every player in this channel on this server Same local behavior as ALL/SERVER. Intended to be filtered cross-server by shard ID in future expansion.
Regardless of scope, a recipient must also satisfy view_permission to receive the message. Players who fail the view permission are silently excluded.

Per-Rank Formats

The channel handler picks the format for a player in this exact order:

rank_formats.<lp_primary_group>
→ not found →
rank_formats.default
→ not found →
formatting.format
→ not found →
channels.formatting.fallback_format

Group names in rank_formats are stored lowercase. The lookup uses the LP primary group string directly, so make sure your rank names match exactly (case is lowercased on the config side).

formatting:
  format: "<gray>[G]</gray> <white><player_name></white><dark_gray>: </dark_gray><white><chat_message></white>"

  rank_formats:
    # "default" catches anyone whose group has no explicit entry here
    default: "<gray>[G]</gray> <white><player_name></white><dark_gray>: </dark_gray><white><chat_message></white>"
    vip:     "<gold>[★ G]</gold> <lp_prefix><gold><player_name></gold><dark_gray>: </dark_gray><yellow><chat_message></yellow>"
    admin:   "<red>[⚡ G]</red> <lp_prefix><red><player_name></red><dark_gray>: </dark_gray><white><chat_message></white>"

Hover Cards

When hover is enabled, the code attaches a hover event to the player's name in the chat component, and also to any online player names that appear in the message body.

chat:
  hover:
    enabled: true
    lines:
      - "<gradient:#FFD700:#FFA500><bold>%player_name%</bold></gradient>"
      - ""
      - "<gray>━━━━━━━━━━━━━━━━━━━━</gray>"
      - "<gold>Stats</gold>"
      - "  <red>❤</red> Health: <white>%player_health%/%player_max_health%</white>"
      - "  <green>✦</green> Level: <white>%player_level%</white>"
      - "  <aqua>⚡</aqua> Ping: <white>%player_ping%ms</white>"

Hover placeholder support

These %placeholder% tokens are replaced inside hover lines before MiniMessage parses them:

%player_name% %player_displayname% %player_uuid% %player_health% %player_max_health% %player_level% %player_ping% %player_world% %player_x% %player_y% %player_z% %player_gamemode% %luckperms_primary_group%

PlaceholderAPI is also run on hover lines first, so any %papi_placeholder% works too.

Default lines when none are configured: the code falls back to two lines — <gold>Player: <white>%player_name%</white></gold> and <gray>Health: <white>%player_health%/%player_max_health%</white></gray>.
Name detection: the hover attach code scans the rendered Adventure Component tree for children whose plain text matches the player's username. This works reliably for most formats. If a custom format splits the name across several styling components, the hover may only attach to a subset of the name characters.

[item] in Chat

When a player types the configured placeholder (default [item]), it is replaced with a clickable component showing the item in their main hand. The replacement happens after MM.deserialize(), directly on the Adventure Component.

chat:
  item-in-chat:
    enabled: true
    placeholder: "[item]"                # case-insensitive match
    empty-hand-text: "<gray>[Air]</gray>"  # shown when main hand is empty

Hover tooltip content

The item component uses item.asHoverEvent() (the native Paper tooltip) as the primary hover source. If that fails, a fallback text hover is built from:

  • Item display name (custom name → lore → friendly material name).
  • Custom ID from ItemsAdder or Nexo if those plugins are installed.
  • All lore lines.
  • Enchantments formatted as Enchant Name I / II / III.
  • Durability in green / yellow / red depending on fraction remaining.
  • Stack size if greater than 1.
ItemsAdder and Nexo are auto-detected on startup. If either is present, the item name and custom ID are resolved through those hooks first. Standard Bukkit meta is used as a fallback.

Discord Bridge

The chat module can forward messages to a Discord channel via webhook. Simple mode and channel mode work slightly differently.

Simple mode (no channels)

chat:
  discord:
    enabled: false
    webhook_url: "https://discord.com/api/webhooks/REPLACE_ME"

When enabled, the plain-text render of the Adventure component is sent to the webhook under the player's username. The raw message (pre-format) is used as the webhook content — not the color-coded format string.

Channel mode

Each channel can define its own discord_webhook. If a channel has no webhook, it falls back to the global webhook (passed from the main init). The webhook username is set to [serverName] #channelDisplayName.

channel_definitions:
  global:
    discord_webhook: "https://discord.com/api/webhooks/REPLACE_ME"

  staff:
    discord_webhook: null  # null = use the global webhook or no webhook at all
Discord receives the raw typed message (plain text), not the MiniMessage-formatted component. Color tags are not included in the Discord message.

Cross-Server Sync

Chat messages are synchronized across servers via RabbitMQ. Each message is serialized as Adventure JSON using GsonComponentSerializer and published to a fanout exchange named chat_sync.

# Bottom of chat-format.yml
MongoDB_rabbitmq:
  enabled: false
  rabbitmq:
    uri: "amqp://guest:guest@localhost:5672/"

When enabled, the ChatSyncManager connects to RabbitMQ on startup with automatic recovery (5-second retry interval). Every message published carries the sender UUID, server name, display name, and the JSON component blob. On the receiving end, the component is deserialized and broadcast to local players.

Channel messages cross-server

In channel mode, channel messages are published on a separate routing key CHANMSG and include the channel ID. The receiving server only broadcasts the message to players who are currently in that same channel.

The server filters out its own messages using a random SERVER_ID UUID generated at startup, so players on the originating server never see a message twice.

Moderation

Mute command

CommandPermissionNotes
/mute <player> <duration> [reason] oreo.mute Duration format examples: 10m, 2h, 1d. Muted players are silently dropped — no message is sent to chat.
/unmute <player> oreo.mute Immediately removes the mute.

Global chat mute & slowmode

Via the ModGui (/modgui), staff can:

  • Mute the entire chat globally — players receive §cChat is currently muted. when they try to send.
  • Enable slowmode — players must wait N seconds between messages. The remaining cooldown is shown in the error.
  • Toggle staff-only chat mode for individual players — messages go to §b[StaffChat] channel visible only to players with oreo.staffchat.

Banned words

Configured in settings.yml under bannedWords. Each match is replaced with asterisks of the same length using a case-insensitive regex. Applied before the format step so the censored text is what gets formatted and synced.

# settings.yml
bannedWords:
  enabled: true
  words:
    - "badword"
    - "anotherbadword"

Join & Quit Messages

Configured in plugins/OreoEssentials/chat-messaging/join-quit-messages.yml.

Join_messages:
  enable: true
  disable_on_backend: true               # suppress on backend servers listed below
  use_backend_list_as: "blacklist"       # "blacklist" or "whitelist"
  backend_server_names:
    - "faction_world"

  look_like_player: true                 # spoof the message as coming from a bot player
  player_name: "<gradient:#9BE8FF:#00D4FF>Oreobot</gradient>"
  join_message_delay: 0                  # ticks to wait before showing join message

  # Default fallback messages using {name} placeholder
  first_join:  "<gradient:...>Welcome {name} to the server for the first time!</gradient>"
  rejoin_message: "<gradient:...>{name} has joined the game.</gradient>"

  # Per-permission overrides — checked top-to-bottom, first match wins
  formats:
    first_join:
      - permission: "oreo.rank.vip"
        text: "<gradient:#FFD700:#FFA500>[VIP]</gradient> <white>{name}</white> <gray>joined for the first time!</gray>"
    rejoin_message:
      - permission: "oreo.rank.vip"
        text: "<gradient:#FFD700:#FFA500>[VIP]</gradient> <white>{name}</white> <gray>is back!</gray>"

  sounds:
    default: "minecraft:entity.player.levelup"
    volume: 1.0
    pitch: 1.0
    formats:
      - permission: "oreo.rank.vip"
        sound: "minecraft:ui.toast.challenge_complete"
FieldMeaning
enableMaster toggle for this section.
disable_on_backendIf true, suppresses messages on servers listed in backend_server_names (or only shows on them if set to whitelist).
look_like_playerIf true, the message is displayed as if sent by the bot player named in player_name.
join_message_delayTicks to delay before sending the join message.
{name}The only placeholder in join/quit message text — replaced with the player's name.
formatsPer-permission override list. Permissions are checked top-to-bottom; first match wins.
sounds.formatsPer-permission sound override. Same top-to-bottom logic.

The Quit_messages section follows the same structure with message instead of first_join / rejoin_message.

Auto Messages & Oreobot

Both live in join-quit-messages.yml.

Automatic messages

Messages sent on a repeating timer, also spoofed as Oreobot if look_like_player: true.

Automatic_message:
  enable: true
  look_like_player: true
  player_name: "<gradient:#9BE8FF:#00D4FF>Oreobot</gradient>"

  messages:
    message1:
      text: "<gradient:...>Don't forget to check our website for updates!</gradient>"
      timer_loop: 50    # fires every 50 seconds (not ticks)

    message2:
      text: "<gradient:...>Type /help for a list of commands!</gradient>"
      timer_loop: 60

Oreobot conversations

The bot can respond to keywords in player chat. Each entry has a keyword (single word) and a key_phrase (multi-word). If either matches, one of the listed replies is chosen at random. The {name} placeholder is replaced with the player's name.

conversations:
  enabled: true
  oreobot:
    custom_call_name: "oreobot"    # players can address the bot by this name
    self_mention_reply: "<gradient:...>Hello, {name}! How can I assist you today?</gradient>"

    questions:
      question1:
        keyword: "help"
        key_phrase: "i need help"
        replies:
          - "<gradient:...>Sure, {name} — what do you need help with?</gradient>"

Troubleshooting

ProblemWhat to check
Chat is not intercepted at all Check settings.yml → features.chat.enabled and chat.enabled: true in chat-format.yml.
Group format not applying The key must be exactly the LP primary group name under chat:, e.g. chat.admin: "...". Case must match the group name LuckPerms returns.
<lp_suffix> shows nothing <lp_suffix> is only injected in channel mode. In simple mode it is not part of the resolver.
Player can see MiniMessage tags others typed The typing player has oreo.chat.colors. Their message is parsed with Placeholder.parsed() which renders MiniMessage tags.
PAPI placeholders in format show as %placeholder% Verify PlaceholderAPI is installed and chat.papi.apply-to-format: true.
Channel scope RANGE never includes certain players RANGE uses Location.distance() which throws if worlds differ. Players in a different world are always excluded.
[item] shows the placeholder text instead of item Check chat.item-in-chat.enabled: true and that placeholder matches exactly what the player typed (check is case-insensitive).
Hover not attaching to the player name Hover works by scanning Adventure component children for text matching the player's name. If the format renders the name across many small style components, the hover may only attach to part of it.
Cross-server messages appear twice on originating server Should not happen — the server filters its own messages using a random UUID generated on startup. If it does happen, check that ChatSyncManager is only initialized once.
Channel mode not activating chat.channels.enabled must be true. After changing it you must /oer reload — the listener type is chosen once at startup (or reload).
After changing chat-format.yml, reload with /oer or /oereload.
For join/quit/death/events files a full reload is also needed — they are not hot-swapped independently.
