AFK System

This page covers the entire AFK module: how inactivity is detected, the auto-AFK timer and permission tiers, all messages players receive, the action bar live timer, tab name changes, the AFK pool (local and cross-server), the RabbitMQ status broadcast, and the embedded web dashboard.

Config file plugins/OreoEssentials/afk/config.yml â€” every AFK setting lives here.
Auto-AFK is off by default Set auto.enabled: true to start flagging inactive players. The default timeout is 300 seconds (5 minutes).
Looking around does not reset the timer Only real block-position changes trigger activity. Pure mouse rotation (head movement) is ignored.

What Counts as Activity

Both AfkService and AfkListener register the same event set. Any of these resets the inactivity clock and, if the player is already AFK, returns them from AFK:

EventCondition checked
PlayerMoveEvent Only fires activity if the block position actually changed (blockX/Y/Z comparison). Looking around without moving does not count.
PlayerInteractEvent Any interaction (right-click, left-click, etc.).
AsyncPlayerChatEvent (legacy) Dispatched to the sync scheduler before touching the AFK state.
AsyncChatEvent (Paper 1.21+) Registered with ignoreCancelled=false so it always fires even when the chat system cancels the event.
PlayerCommandPreprocessEvent Counts as activity except for /afk itself. The check is a case-insensitive prefix match on the first four characters.
AFK pool exemption: while a player is inside the AFK pool region, movement events do not feed back into the inactivity clock. The pool has its own movement handler that returns the player when they actually walk out of the pool.
Grace window: when a player is teleported into or out of the AFK pool, movement is suppressed for 1 500 ms (1.5 seconds) to prevent the teleport itself from immediately triggering an AFK return or re-entry.

Auto-AFK Timer

When auto.enabled: true, a repeating task checks all online players every check-interval-seconds seconds. If a player has not triggered any activity for at least seconds seconds, they are automatically flagged AFK.

auto:
  enabled: true        # false = auto-AFK disabled; players can still /afk manually
  seconds: 300         # default timeout â€” 300 s = 5 minutes (minimum 0, clamped by code)
  check-interval-seconds: 5   # poll rate (minimum 1 second, clamped by code)

The task runs on the main server thread at 20 Ã— check-interval-seconds ticks. Each iteration only checks players who are not already AFK. If a player with no recorded activity yet joins, their clock starts from join time.

Setting seconds: 0 disables the auto timeout (the code clamps the value to max(0, ...)). A value of 0 is treated as "no auto timeout" because the check condition is inactiveSeconds >= timeout && timeout > 0.

Permission Tiers

Permission tiers let you give specific groups a longer timeout before being auto-flagged. The list is checked top-to-bottom; the first matching permission wins.

auto:
  seconds: 300   # default for anyone with no matching tier

  permission-tiers:
    - permission: oreo.afk.tier.farm   # checked FIRST
      seconds: 600                      # 10 minutes for farmers
    - permission: oreo.afk.tier.vip
      seconds: 450                      # 7.5 minutes for VIPs
    # Players with neither permission use the default 300 s above

If a player has multiple tier permissions, only the first match in the list is used. Order your list from most-specific / longest timeout to least-specific.

To give a rank an infinite timeout (never auto-AFK), give them a tier with a very large seconds value, or simply do not put them in any tier and set the global seconds to 0 (which disables auto-AFK for everyone).

AFK Messages

Three messages are sent to the player at different points in the AFK lifecycle. All use MiniMessage format. The text comes from the lang file unless overridden by a custom-message entry (see next section).

WhenLang keyHardcoded fallback
Player enters AFK afk.now-afk <yellow>You are now AFK.</yellow>
Player leaves AFK afk.no-longer-afk <green>You are no longer AFK.</green>
Player leaves AFK (duration report) afk.back-message <green>You were AFK for <white>%time%</white>.</green>

The back-message (duration report) is only sent if back-message.enabled: true and the player was AFK for at least 1 second. %time% is replaced with a human-readable duration like 5m 12s or 1h 3m 40s.

back-message:
  enabled: true   # set false to suppress the duration report entirely

Custom Messages Per Permission

You can override any or all three AFK messages for specific permission groups. The list is checked top-to-bottom; the first permission the player has wins. If a key is omitted, the default lang message is used for that key.

    now-afk:     "<red>[Admin] You are now AFK.</red>"
    no-longer-afk: "<red>[Admin] Back.</red>"
    back:        "<red>[Admin] Away for <white>%time%</white>.</red>"

  - permission: oreo.afk.vip
    now-afk: "<gold>[VIP] You are now AFK.</gold>"
    no-longer-afk: "<gold>[VIP] Welcome back!</gold>"
    back: "<gold>[VIP] You were AFK for <white>%time%</white>.</gold>"
    # If you omit "back" here, the default lang message is sent instead

Action Bar Timer

When actionbar.enabled: true, AFK players receive a live action bar message every second showing how long they have been AFK.

actionbar:
  enabled: true   # set false to disable the live timer action bar

The text comes from the lang key afk.actionbar. The hardcoded fallback is:

<gray>AFK for <white>%time%</white></gray>

%time% is replaced with the same human-readable duration format used by the back-message. The action bar updates exactly every 20 ticks (1 second) using an entity-safe scheduler compatible with Folia.

Tab List Name

When a player goes AFK, their tab list name is changed to prefix their original name with Â§7[AFK] Â§r. The original tab name is captured before the change and restored exactly when they return.

AFK state tab name format

Â§7[AFK] Â§r<original_tab_name>

This is set via Bukkit's player.setPlayerListName(). There is no config option to change this format â€” edit the source if you need a different prefix.

Restore on return

The original name is stored in memory when AFK begins (originalTabNames map). On return, the stored name is restored. On player quit, all AFK state including the stored name is cleaned up.

If a third-party tab plugin (like TAB or FeatherBoard) also sets the player list name, it may conflict. The AFK module calls setPlayerListName() directly on the Bukkit API without coordinating with external plugins.

AFK Pool â€” Overview

The AFK pool teleports players into a dedicated safe area (a WorldGuard region) when they go AFK, and returns them to their original location the moment they move again.

1
Create a WorldGuard region named afk_pool (or whatever you set in pool.region-name) in the world specified by pool.world-name.
2
Enable the pool in the config: pool.enabled: true. Reload with /oer.
3
Test it: go AFK with /afk. You should be teleported to the center of the region. Any movement while inside will return you to your original position.
The teleport destination is calculated as the center of the WorldGuard region's bounding box: x = (min.x + max.x) / 2 + 0.5, z = (min.z + max.z) / 2 + 0.5, y = min.y + 1. Make sure there is at least 2 blocks of vertical clearance at that point.

Local Pool Setup

pool:
  enabled: true
  region-name: "afk_pool"   # exact WorldGuard region ID
  world-name: "world"       # Bukkit world name where the region lives
  server: ""                # leave empty for local-only pool
  cross-server: false

PacketManager retry: if RabbitMQ is not yet ready when a player goes AFK, the pool service waits 40 ticks (2 seconds) and retries once. If it is still not ready, the player receives the afk.pool.not-ready message and is not teleported. Ensure RabbitMQ is connected before the first player goes AFK.
Pending teleports on disconnect: if a player disconnects while a cross-server pool teleport is in flight, the return location is saved in the pendingReturnTeleports map. When they reconnect to the origin server, they are automatically teleported to their original location 1 second (20 ticks) after join.

Cross-Server Status Sync

Independently of the pool, AFK enter/exit events are broadcast to all other servers via AfkStatusPacket over RabbitMQ whenever RabbitMQ is initialized. This powers the global view in the web dashboard.

AfkStatusPacket payload

FieldTypeValue
playerIdUUIDThe AFK player's UUID.
playerNameStringThe player's username.
serverStringThe server name from config.yml.
worldNameStringThe Bukkit world name the player is in.
x / y / zdoublePlayer coordinates at the moment of AFK entry.
afkSinceMslongUnix epoch milliseconds when AFK started.
enteringbooleantrue = player went AFK, false = player returned.

Receiving servers store incoming data in their own globalAfkData map (keyed as "server:uuid") and use it to populate the web dashboard. A server ignores packets from itself using a case-insensitive server-name comparison.

No configuration is required for cross-server status sync â€” it activates automatically whenever the PacketManager (RabbitMQ) is initialized. If RabbitMQ is not configured, status sync is silently skipped.

Web UI & JSON API

An optional embedded HTTP server exposes AFK data as both a human-readable dashboard and a machine-readable JSON endpoint.

  enabled: true
  port: 8765   # the HTTP server binds to 0.0.0.0:<port>

HTML page showing a table of all currently AFK players (local + cross-server). Auto-refreshes every 10 seconds. Displays: player name, server badge, world, coordinates, and live AFK duration.

Troubleshooting

ProblemWhat to check
Players are never auto-flagged AFK Confirm auto.enabled: true and auto.seconds > 0. Also verify they do not have a permission-tier that sets their timeout very high.
Looking around resets the AFK timer It should not â€” the code compares blockX/Y/Z only. If it is resetting, another plugin may be re-dispatching a move event with a modified position.
AFK timer resets when typing /afk It should not â€” /afk is excluded in AfkListener. Any other command counts as activity.
Tab name not changing A third-party tab plugin may be overwriting setPlayerListName(). The AFK module does not hook into external tab managers.
Action bar not showing Check actionbar.enabled: true. If that is fine, the lang key afk.actionbar may be returning an empty string.
Pool teleport target is wrong (inside a block, offset) The target is (min + max) / 2 centered at block center, y = min.y + 1. Make the region at least 1 wide and 2 tall at its center point.
Pool immediately returns the player The 1 500 ms grace window may be expiring too fast for laggy players. The window starts when the teleport is issued, not when the player arrives. Increase it in the source if needed.
Cross-server pool never sends the player RabbitMQ must be initialized first. The pool retries once after 2 seconds. Check that pool.server exactly matches the BungeeCord server name and that RabbitMQ is running.
Web dashboard shows only local players Cross-server data requires RabbitMQ. Without it the globalAfkData map only contains local entries. The dashboard shows all entries in that map.
Web server port conflict on startup Another process is already using the port. Change web.port to a free port and reload.
