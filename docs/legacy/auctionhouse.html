Module Documentation

Auction House

A fully-featured player-driven marketplace built into OreoEssentials. Players can list items for sale, browse or search what others have listed, buy instantly, manage their own listings, and reclaim anything that expires. The AH works on a single server or syncs in real time across a whole network via RabbitMQ.

Config files plugins/OreoEssentials/auctionhouse/
config.yml · messages.yml · categories.yml · gui.yml
Storage JSON (default) or MongoDB. Auto-saves every 5 minutes. Cross-server sync via RabbitMQ packets.
Economy Vault (default) or any custom currency registered with CurrencyService. Per-listing currency choice.

config.yml — Every Setting Explained

This is the main config file. All other YAML files (messages, categories, gui) live in the same folder. After editing, run /ahadmin reload to apply changes without restarting. 

# plugins/OreoEssentials/auctionhouse/config.yml

enabled: true          # Set to false to completely disable the auction house.

storage:
  type: auto           # "auto"    → uses MongoDB if connected, otherwise JSON
                       # "json"    → always use local JSON files
                       # "mongodb" → always use MongoDB (requires OreoEssentials MongoDB connection)
  mongodb:
    collection: oreo_auctions   # Name of the MongoDB collection to store auctions in.

listings:
  min-price: 1.0                  # Lowest price a player is allowed to set. (default: 1.0)
  max-price: 1000000000.0         # Highest price a player is allowed to set. (default: 1 billion)
  max-per-player: 10              # How many active listings one player can have at once.
  default-duration-hours: 24      # How long a listing lasts if the player doesn't pick a duration.
  max-duration-hours: 168         # Maximum duration a player can request (168h = 7 days).

fees:
  listing-percent: 0.0   # % of the item price charged to the seller when they list. 0 = free.
  listing-flat: 0.0      # Flat fee charged to the seller when they list (on top of percent).
  tax-percent: 0.0       # % deducted from the seller's earnings when the item is sold. 0 = no tax.

discord:
  enabled: false
  webhook-url: ""         # Paste your Discord webhook URL here.
  bot-name: "OreoAuctions"
  bot-avatar: ""          # URL to an avatar image for the Discord bot (optional).

How fees work — a concrete example

Suppose listing-percent: 5, listing-flat: 10, and tax-percent: 3. A player lists an item for $1000:

1
Listing fee charged immediately
5% of 1000 = $50 + $10 flat = $60 total taken from the seller's balance right now.
2
Buyer pays $1000 — the full listed price, no extra charge.
3
Tax deducted from seller's earnings
3% of 1000 = $30 → seller receives $970.
Tip: If all fees are 0.0 (default), listing and buying are completely free with no deductions.

How to Sell an Item

There are two ways to list an item. Both require the item to be in your main hand.

Method 1 — Quick sell with a price argument

Hold item in hand
→
/ahs 500
→
SellGUI opens (pick category)
→
ConfirmGUI
→
Listed!

/ahs <price> — sets the price immediately and opens the SellGUI. Uses Vault (the server's default economy) as the currency.
You can also add a custom duration in hours as a second argument: /ahs 500 48 (list for 48 hours instead of the default).

Method 2 — GUI sell (currency picker)

Hold item in hand
→
/ahs (no price)
→
CurrencyPickerGUI
→
Type price in chat
→
SellGUI (pick category)
→
ConfirmGUI
→
Listed!

Running /ahs with no price argument opens the CurrencyPickerGUI. Here the player clicks to pick which currency to sell for (Vault or a custom currency). After picking, the chat waits for the player to type a price. Once typed, the SellGUI opens.

What happens at the SellGUI? The SellGUI shows the item and price. The player must click a category to assign their listing to (e.g. Weapons, Armor, Tools…). After picking a category, a ConfirmGUI opens as a final confirmation step. Clicking confirm removes the item from your hand, charges the listing fee (if any), and creates the listing.

Listing limits enforced at sell time

  • Price must be ≥ listings.min-price and ≤ listings.max-price.
  • Player must have fewer than listings.max-per-player active listings.
  • Player must have enough money to cover the listing fee (percent + flat).
  • If any check fails, the player gets an error message and nothing happens.

How to Buy an Item

/ah
→
Browse GUI
→
Click the item
→
ConfirmGUI
→
Confirm purchase
→
Item in your inventory

In the browse GUI, click any listing to open the ConfirmGUI. It shows the item, price, seller name, and time remaining. Click the confirm button to purchase. If you click cancel, you're sent back to the browse screen with no charge.

What happens behind the scenes when you buy

1
Buyer's balance is checked — must have enough for the full listed price.
2
Money is transferred — buyer pays the full price. The seller receives the price minus the tax-percent (if configured).
3
Item is given to buyer — added to their inventory. If their inventory is completely full, the item is dropped at their feet (it is never lost).
4
Listing is removed — the auction moves to SOLD status. The seller is notified if they are online. A cross-server PURCHASE sync packet is broadcast so all servers update immediately.
Buying your own listing: In the browse GUI, if you click on a listing that belongs to you, you are sent to the ManageGUI instead of the ConfirmGUI (you can't buy from yourself).

Managing Your Listings

Click "Your Listings" in the browse GUI (or click your own listing directly) to open the ManageGUI. This shows all your currently active listings.

Click any item in the ManageGUI to cancel that listing. Cancelling returns the item directly to your inventory. If your inventory is full, the item is dropped at your feet.

Listing fee is not refunded on cancel. The listing fee (if any) was charged when you created the listing and is not returned if you cancel or if the listing expires.

Expired & Sold Items

Expired items

Every 60 seconds, the server checks all active listings. Any listing whose expiration time has passed is moved to the expired list. If the seller is currently online, they receive a chat notification. Items in the expired list stay there until the player reclaims them.

Run /ahexpired to open the ExpiredGUI. Click any item in this GUI to reclaim it (it goes back into your inventory or drops at your feet if full). Expired items are not given back automatically — the player must manually reclaim them.

Sold history

Run /ahsold to open the SoldGUI. This shows items you have successfully sold, including the buyer name, price received, and when the sale happened. This is read-only history.

Time display format

Time remaining is shown in the format Xd Xh Xm Xs. Seconds are hidden once the listing is 1+ day away. Examples:

Remaining timeDisplayed as
2 days, 3 hours, 15 minutes2d 3h 15m
5 hours, 30 minutes, 45 seconds5h 30m 45s
12 minutes, 3 seconds12m 3s
Expired or 0Expired

Live refresh on cross-server events

When any server in the network creates, sells, cancels, or expires a listing, an AuctionSyncPacket is broadcast via RabbitMQ. All servers that receive it update their in-memory auction lists and immediately refresh the GUI for every player currently browsing — so what you see is always up-to-date, even across servers.

Search System

Use /ahsearch <keyword> or click the search button in the browse GUI. Requires at least 2 characters. The search is case-insensitive and checks:

  • Item type name — e.g. searching "diamond" matches DIAMOND_SWORD, DIAMOND_PICKAXE, etc.
  • Display name — the item's custom name in Minecraft (color codes stripped).
  • Lore lines — any line in the item's description (color codes stripped).
  • Seller name — e.g. searching "Steve" shows all of Steve's listings.
  • Custom item IDs — ItemsAdder namespace:id, Nexo item ID, or Oraxen item ID.

You can combine search with a category filter: the browse GUI supports both at the same time. Click the "Clear Search" button (slot 45 in browse) to remove the search query while keeping the category filter active.

Categories

Every listing has exactly one category. When a player lists an item, they pick a category in the SellGUI. If an admin wants auto-detection, the code in AuctionCategory.fromItem() follows this priority order:

Auto-detection priority (used internally)

1
CUSTOM — if the item has CustomModelData, OR is detected as an ItemsAdder / Nexo / Oraxen item. Custom items always go here first, regardless of their material.
2
SPAWNERS — if material is SPAWNER or any *_SPAWN_EGG.
3
WEAPONS — material name contains SWORD, BOW, CROSSBOW, TRIDENT, or is MACE.
4
ARMOR — material name contains HELMET, CHESTPLATE, LEGGINGS, BOOTS, or is SHIELD.
5
TOOLS — material name contains PICKAXE, AXE, SHOVEL, HOE, or is SHEARS, FISHING_ROD, FLINT_AND_STEEL, BRUSH.
6
FOOD — material.isEdible() returns true.
7
POTIONS — material name contains POTION or is TIPPED_ARROW.
8
BLOCKS — material.isBlock() returns true.
9
MISC — everything else that doesn't match above.

Category browse permissions

A player can view a category if they have oreo.ah.bypass, oreo.ah.category.*, or the specific permission for that category (e.g. oreo.ah.category.weapons). By default, all players have access to all categories.

Fee System

The AH supports three independent fees. All default to 0.0 (no fees).

Config keyWhen chargedWho paysDescription
fees.listing-percent At listing creation Seller Percentage of the listed price. E.g. 5 = 5% of the price deducted from seller's wallet when listing is created.
fees.listing-flat At listing creation Seller Flat amount (in default currency). Charged in addition to listing-percent. E.g. 100 = $100 no matter the price.
fees.tax-percent When the item sells Seller (deducted from earnings) Percentage of the sale price kept as tax. E.g. 10 = seller only receives 90% of the sale price.
Listing fees are never refunded — if you cancel your listing or it expires, the listing fee you paid when creating it is not returned.

Multi-Currency Support

Each listing stores a currencyId field. If this field is null (or empty), the listing uses Vault — the standard server economy. If it contains a string ID, that ID is passed to OreoEssentials' internal CurrencyService to look up a custom currency (e.g. "gems", "tokens").

When a player runs /ahs without a price argument, the CurrencyPickerGUI appears, letting them choose which currency to price their item in. When they run /ahs 500 (with a price), Vault is used directly — no picker shown.

Currency is per-listing, not global. Two listings by the same player can use different currencies. The browse GUI shows the currency name next to the price if it's not Vault.

Storage Backends

The AH keeps all active auctions in memory for fast access. Storage backends are used for persistence (saving to disk so data survives restarts).

TypeWhen usedDetails
auto (default) On startup Uses MongoDB if OreoEssentials has a live MongoDB connection; otherwise falls back to JSON.
json Always Saves to a local JSON file inside plugins/OreoEssentials/auctionhouse/. Simple, requires no database. Auto-saves every 5 minutes (300 seconds).
mongodb Always Uses a MongoDB collection (default name: oreo_auctions). Suitable for large servers or networks. Auto-saves every 5 minutes.

Auto-save & expiry tasks

  • Expiry check: runs every 60 seconds. Moves listings past their expiration time to the expired list and notifies online sellers.
  • Auto-save: runs every 300 seconds (5 minutes). Writes the full in-memory state to whichever backend is active.
  • Both tasks are scheduled using the OreoScheduler (Folia-safe).

Item serialization

Items are serialized to a Base64 string using Bukkit's BukkitObjectOutputStream and stored alongside the auction data. This preserves all enchantments, NBT data, and custom model data exactly. Custom plugin item IDs (ItemsAdder, Nexo, Oraxen) are stored as separate string fields so they can be displayed as badges in the GUI.

Cross-Server Sync (RabbitMQ)

In a network (BungeeCord / Velocity), all servers share the same auction house. Any action on one server is broadcast to all others via a AuctionSyncPacket over RabbitMQ.

ActionPacket containsWhat receiving servers do
CREATE Full auction data: seller UUID + name, item (Base64), price, times, category, currency, custom IDs Add the new auction to their in-memory list and refresh all open browse GUIs.
PURCHASE Auction ID, buyer UUID + name Mark the auction as SOLD, remove from active list, refresh all open browse GUIs. If the seller is online, notify them.
CANCEL Auction ID only Remove from active list, refresh browse GUIs.
EXPIRE Auction ID only Move to expired list, refresh browse GUIs.
The originating server ignores sync packets from itself. Packets carry the originServer field so receiving servers can filter them out.

GUI live-refresh

When a sync packet arrives, the module calls refreshAllBrowseViewers(). This iterates over every player currently viewing a browse GUI (tracked in a ConcurrentHashMap) and re-opens the GUI for their current page and filter. Players see changes within milliseconds of them happening on any server.

Troubleshooting

ProblemLikely cause & fix
"/ah" says "auction house is disabled" Check enabled: true in config.yml. Run /ahadmin reload after changing it.
Player can't list — "max listings" error immediately Their active listing count equals listings.max-per-player. Increase it, or have the player cancel old listings.
Item appears in the wrong category after listing The player manually picked a category in the SellGUI. Auto-detection only applies internally; the player's choice overrides it.
Listing fee is charged but player gets an error afterward This shouldn't happen — listing fee is charged only on success. If it does, check for exceptions in the console (item serialization failure, etc.).
Bought item not in inventory — where did it go? If inventory was full, the item was dropped at the player's feet. Check the ground where they were standing. A chat message also tells them this happened.
Cross-server sync not working RabbitMQ must be connected. Check that AuctionSyncPacket is registered in registerAllPacketsDeterministically() and that subscribeCrossServerEvents() is called in initRabbitMQ().
MongoDB: auctions not saving Verify the MongoDB connection is alive and the collection name (storage.mongodb.collection) is correct. Check console for connection errors on startup.
JSON: data lost on restart Auto-save runs every 5 minutes. If the server crashed unexpectedly, the last 5 minutes of listings may be lost. Run /ahadmin save before planned restarts.
PAPI placeholders return empty string Ensure PlaceholderAPI is installed and the AH module initialized successfully. Check for errors in the console at startup.
/ahsearch with one character does nothing This is intentional — at least 2 characters are required to prevent very broad searches.
