Scoreboard, Tab, and BossBar

This page explains the current OreoEssentials UI systems the way the code actually reads them today. It covers the right-side scoreboard, the TAB list, the simple boss bar, and the multi-bossbar system from custom-nameplates/config.yml. Where the code has limits or caveats, they are called out directly.

Best reload command Use /oer or /oereload after config changes unless you are reloading a smaller module on purpose.
BossBar recommendation The multi-bossbar system is the main one now. The simple bossbar still exists, but it is disabled by default in settings.yml.
Important condition limit Current code supports world, region, permission, gamemode, and PAPI checks. It does not support regex world matching.

Overview

There are four different UI pieces involved here. They do not all live in the same file.

System What players see Main config file Toggle / command
Scoreboard Sidebar on the right side of the screen plugins/OreoEssentials/scoreboard-tab/scoreboard.yml /scoreboard, alias /sb, permission oreo.scoreboard.toggle
Tab list Player list shown when TAB is pressed plugins/OreoEssentials/scoreboard-tab/tab.yml Feature toggle only: settings.yml -> features.tab.enabled
Simple BossBar One global bar at the top of the screen plugins/OreoEssentials/config.yml under bossbar: /bossbar toggle, permission oreo.bossbar.toggle, plus settings.yml -> features.bossbar.enabled
Multi BossBar Multiple named bars, each with its own conditions plugins/OreoEssentials/custom-nameplates/config.yml under bossbars: Enabled from that file; also affected by UI safeguards

Before You Start

1
Turn the module on in settings.yml.

The code respects feature toggles first. If a feature is off there, editing the YAML for that feature will not do anything.

features:
  scoreboard:
    enabled: true

  tab:
    enabled: true

  bossbar:
    enabled: false   # simple legacy bossbar, off by default in your file
2
Know which bossbar system you want.

If you want one simple bar for everybody, use config.yml -> bossbar:. If you want different bars for different players, worlds, ranks, or regions, use custom-nameplates/config.yml -> bossbars:.

3
Reload after edits.

Use /oer or /oereload. That is the safest general command for these files.

Important: if you enable both the simple bossbar and the multi-bossbar system, players can receive both. Usually that is not what you want.

Scoreboard Basics

The scoreboard is loaded from plugins/OreoEssentials/scoreboard-tab/scoreboard.yml. The parser reads exactly these keys:

Path Type What it does
scoreboard.default-enabled boolean Default state for players who have never toggled the scoreboard yet
scoreboard.update-ticks number Refresh cadence. Minimum is 1 tick in code.
scoreboard.title.frame-ticks number How often the title animation advances
scoreboard.title.frames list Animated title frames
scoreboard.worlds.whitelist list If not empty, only those worlds may show the scoreboard
scoreboard.worlds.blacklist list If a world appears here, the scoreboard is blocked there
scoreboard.lines list Every visible row in the sidebar

Minimal working example

scoreboard:
  default-enabled: true
  update-ticks: 20

  title:
    frame-ticks: 10
    frames:
      - "&9&lOreo&b&lEssentials"

  worlds:
    whitelist: []
    blacklist: []

  lines:
    - "&7Player: &b{player}"
    - "&7Rank: %luckperms_prefix%%luckperms_primary_group%"
    - "&7Money: &e%vault_eco_balance_formatted%"
Player command: players toggle this with /scoreboard or /sb. The permission is oreo.scoreboard.toggle, and the chosen state is persisted for that player.

Scoreboard Title and Line Animation

The title animates from scoreboard.title.frames. The lines can also animate with the built-in tag parser.

Animated title

scoreboard:
  title:
    frame-ticks: 10
    frames:
      - "&9&lOreo&b&lEssentials"
      - "&b&lOreo&9&lEssentials"
      - "&f&lOreo&3&lEssentials"

Animated line syntax

The parser looks for this exact pattern:

%animations_<tag interval=5>
Frame one
|
Frame two
|
Frame three
</tag>%

That means:

  • interval=5 means each frame lasts 5 ticks. If you omit the interval= part entirely (e.g. %animations_<tag>), the code defaults to 20 ticks.
  • A line that only contains | separates frames.
  • The whole block must start with %animations_<tag ...> and end with </tag>%.

Real example

- |-
  %animations_<tag interval=10>
  <gradient:#FFD700:#FFA500>Balance:</gradient> &e%vault_eco_balance_formatted%
  |
  <gradient:#FFA500:#FFD700>Balance:</gradient> &6%vault_eco_balance_formatted%
  |
  <gradient:#FFFF00:#FFD700>Balance:</gradient> &e%vault_eco_balance_formatted%
  </tag>%

Scoreboard World Filters

The scoreboard code checks the current world name against both lists.

scoreboard:
  worlds:
    whitelist:
      - world
      - survie
    blacklist:
      - event_world
  • If whitelist is not empty, only those worlds can show the scoreboard.
  • If blacklist contains the current world, the scoreboard is blocked there.
  • The world names are compared as exact strings here, so use the real Bukkit world names.
If a player tries to turn the scoreboard on in a blocked world, the code sends the "scoreboard is disabled in this world" message instead of forcing it on.

Tab Overview

Tab is loaded from plugins/OreoEssentials/scoreboard-tab/tab.yml. The top-level choices that matter first are:

tab:
  enabled: true
  use-placeholderapi: true
  interval-ticks: 20
  layout-mode: CLASSIC   # or CUSTOM
Field Meaning Important code note
enabled Legacy file-local toggle The real master switch is still settings.yml -> features.tab.enabled.
use-placeholderapi Allows PlaceholderAPI resolution in TAB strings Only works if PlaceholderAPI is installed
interval-ticks Refresh cadence Code clamps this to a minimum of 20, even if the file says 2
layout-mode CLASSIC or CUSTOM CUSTOM requires ProtocolLib or the code falls back to classic

Tab Join Title

The tab system also has a join-title block in tab.title. This is separate from the tab header/footer itself.

tab:
  title:
    enabled: true
    show-on-join: true
    text: "&9&lOREO&b&lESSENTIALS"
    subtitle: "&7Welcome &b%player_displayname%&7!"
    fade-in: 10
    stay: 60
    fade-out: 10
  • enabled must be true or nothing is sent.
  • show-on-join must also be true for automatic join display.
  • text and subtitle support the same normal color/PAPI processing path as the rest of the tab manager.
  • fade-in, stay, and fade-out are passed directly to the title send call.

Classic Tab Mode

Classic mode uses the normal Minecraft player list and only changes the header, footer, and player list names.

tab:
  layout-mode: CLASSIC
  header: "&6Welcome &e%player_name%"
  footer: "&7Players online: &b%oe_local_online%"

  name-format:
    enabled: true
    use-rank-formats: true
    rank-key: "%luckperms_primary_group%"
    server-tag: " &8(&7%server_name%&8)"
    pattern: "%luckperms_prefix%%player_name%%oe_server_tag%"
    rank-formats:
      default: "&7%nick_or_name%"
      admin: "&c[Admin] &f%nick_or_name%"
    enforce-max-length: false
    max-length: 64
    overflow: TRIM

Name format fields

Field What it does
enabled Turns player list name formatting on or off
use-rank-formats If true, the code first tries rank-formats using the value resolved from rank-key
rank-key Usually a PAPI placeholder such as %luckperms_primary_group%
pattern Fallback format if no rank-specific format matches
server-tag Used by the built-in placeholder %oe_server_tag%
enforce-max-length, max-length, overflow Length control for the final rendered player list name

Classic header/footer animations

The classic header and footer also support the built-in animation tag parser.

tab:
  layout-mode: CLASSIC
  header: |-
    %animations_<tag interval=20>
    &6Welcome
    |
    &eWelcome
    </tag>%
  footer: "&7Players online: &b%oe_local_online%"

Custom Tab Mode

Custom mode builds a packet-based layout with a top section, a player section, and a bottom section.

tab:
  layout-mode: CUSTOM

  custom-layout:
    change-interval: 80

    top-section:
      texts:
        - "&6Welcome"
        - "&eWelcome"

    player-section:
      enabled: true
      player-format:
        format: "%luckperms_prefix%%player_displayname%%afk_indicator%"
        rank-colors:
          admin: "&b"
          default: "&f"
        show-afk: true
        afk-format: " &7AFK"

    bottom-section:
      texts:
        - "&7Players: &b%oe_network_online%"
        - "&7Website: &dexample.com"

    sorting:
      rank-priority:
        admin: 100
        mod: 80
        default: 10

How the code reads custom mode

  • change-interval is the frame-change speed for animated top and bottom text.
  • If top-section.texts exists, those frames are used.
  • If top-section.texts does not exist, the code falls back to line-1, line-2, and line-3.
  • The same fallback exists for bottom-section.
  • player-section.enabled: false disables the custom player rows. When that happens, name-format is used to format names instead.
  • The live sort key in code is the resolved rank priority from sorting.rank-priority.
The sample YAML may contain extra keys such as sorting.method: RANK, custom-layout.enabled, or show-ping-bars, but the current tab code does not read them. The meaningful custom-layout keys today are the ones documented here, especially change-interval, top/bottom text blocks, player-format, and sorting.rank-priority.

Tab Cross-Server Behavior

The classic TAB manager supports a network block:

tab:
  network:
    all-servers: true
    excluded-servers:
      - hub

When classic mode builds header/footer strings, it can fill these internal placeholders:

Placeholder Meaning
%oe_local_online% Current local Bukkit online count
%oe_network_online% Network player count if PlayerDirectory data exists; otherwise local count
%oe_network_list% One line per player in the form Name (server)
%oe_server_tag% The text from tab.name-format.server-tag

Custom layout placeholder scope

The custom layout renderer does not use the same internal placeholder resolver as classic mode. The direct built-ins it injects itself are narrower:

%player_displayname% %player_name% %player_world% %player_ping% %oe_network_online%
Exact code caveat: in custom layout, %oe_network_online% is filled from the current local online count in that renderer path, and the classic built-ins like %oe_local_online%, %oe_network_list%, and %oe_server_tag% do not go through the same classic placeholder resolver there. So if you want the most accurate cross-server placeholder behavior, classic header/footer is the safer path today.

Per-World Overrides

Per-world entries are read from tab.per-world. The world key lookup is case-insensitive here.

tab:
  per-world:
    survie:
      header: "<green>Survival World"
      footer: "<gray>Type /help for commands"
      use-placeholderapi: true

      name-format:
        enabled: true
        pattern: "&a%nick_or_name%"

      conditions:
        - type: PERMISSION
          value: oreo.vip
Field inside one world entry Meaning
header Overrides the normal classic header for that world
footer Overrides the normal classic footer for that world
use-placeholderapi World-level PAPI toggle override
name-format World-level override of the normal name-format block
conditions All of these must pass or the whole world override is ignored
Header and footer overrides are for classic mode. The name-format override can still matter in custom mode if player-section.enabled: false and the code falls back to name-format.

Conditions System

The same condition model is reused by tab overrides, holograms, and bossbars. Every listed condition must pass. If one fails, the entry fails.

Type Needs Example
PERMISSION Nothing extra value: oreo.vip
GAMEMODE Nothing extra value: CREATIVE
WORLD Nothing extra value: survie — comparison is case-insensitive
REGION WorldGuard value: spawn
PAPI_EQUALS PlaceholderAPI placeholder: "%luckperms_primary_group%" and value: vip
PAPI_CONTAINS PlaceholderAPI value: staff
PAPI_GREATER PlaceholderAPI value: "1000"
PAPI_LESS PlaceholderAPI value: "10"

Condition syntax

conditions:
  - type: PERMISSION
    value: oreo.vip

  - type: PAPI_EQUALS
    placeholder: "%luckperms_primary_group%"
    value: "vip"

Negation

conditions:
  - type: PERMISSION
    value: oreo.staff
    negate: true   # passes only if the player does NOT have that permission
No regex world support: the current code does not have a regex world condition. World matching is a direct world-name equality check.

BossBar Overview

You have two bossbar systems in this codebase.

System Where it lives Best use
Simple BossBar config.yml -> bossbar: One global bar for everybody, with optional conditions
Multi BossBar custom-nameplates/config.yml -> bossbars: Several named bars with different target audiences and carousel text
The code comments and default settings clearly push the plugin toward the multi-bossbar system. Use the simple bossbar only if you really want one legacy global bar.

Simple BossBar

The simple bossbar is still read by BossBarService. It pulls from config.yml -> bossbar: and respects settings.yml -> features.bossbar.enabled.

bossbar:
  text: "<gradient:#FF1493:#00FF7F>Welcome</gradient> {player}"
  color: PURPLE
  style: SEGMENTED_10
  progress: 1.0
  update-ticks: 40
  conditions: []
Field Meaning
text Single rendered message. Supports {player} and PlaceholderAPI.
color BLUE, GREEN, PINK, PURPLE, RED, WHITE, YELLOW
style SOLID, SEGMENTED_6, SEGMENTED_10, SEGMENTED_12, SEGMENTED_20
progress Clamped from 0.0 to 1.0 by code
update-ticks Refresh cadence. Minimum is 1 tick in code.
conditions Optional condition list. If present, all must pass for the player to see the bar.
Players can toggle this bar with /bossbar toggle. The permission is oreo.bossbar.toggle.

Multi BossBar

The multi-bossbar system is loaded from custom-nameplates/config.yml under bossbars:. Each bar has its own ID and conditions.

bossbars:
  enabled: true
  refresh-interval-ticks: 40

  bars:
    welcome:
      texts:
        - "<gradient:#ff6b6b:#ffd93d>Welcome to the server!</gradient>"
        - "<gray>Type /help for a list of commands"
      carousel-interval-ticks: 100
      color: PURPLE
      style: SOLID
      progress: 1.0
      conditions: []

    staff-bar:
      text: "<red>Staff mode active"
      color: RED
      style: SEGMENTED_10
      progress: 1.0
      conditions:
        - type: PERMISSION
          value: oreo.staff

What the parser accepts

Path Meaning
bossbars.enabled Turns the multi-bossbar service on or off
bossbars.refresh-interval-ticks How often all bar conditions and titles are refreshed
bossbars.bars.<id>.texts List of rotating titles
bossbars.bars.<id>.text Single fallback title if you do not want a list
bossbars.bars.<id>.carousel-interval-ticks Frame speed for that one bar
bossbars.bars.<id>.color, style, progress Visual settings for that one bar
bossbars.bars.<id>.conditions Who gets that bar
The code creates and removes each named bar independently. That means one player can satisfy several bars and see several bossbars stacked.

Carousel and Real Examples

Carousel support exists only when you provide multiple text frames.

VIP world bar

vip-world:
  texts:
    - "<gold>VIP zone"
    - "<yellow>Welcome back, %player_name%"
  carousel-interval-ticks: 80
  color: YELLOW
  style: SOLID
  progress: 1.0
  conditions:
    - type: WORLD
      value: survie
    - type: PAPI_EQUALS
      placeholder: "%luckperms_primary_group%"
      value: "vip"

Region-only arena bar

arena-warning:
  text: "<red>You are in the PvP arena"
  color: RED
  style: SEGMENTED_6
  progress: 1.0
  conditions:
    - type: REGION
      value: pvp_arena

Players below level 10

beginner-help:
  text: "<aqua>Tip: Type /help"
  color: BLUE
  style: SOLID
  progress: 1.0
  conditions:
    - type: PAPI_LESS
      placeholder: "%player_level%"
      value: "10"

Everybody except staff

non-staff-news:
  text: "<green>Season reset this weekend"
  color: GREEN
  style: SOLID
  progress: 1.0
  conditions:
    - type: PERMISSION
      value: oreo.staff
      negate: true

Troubleshooting

Problem What to check
Custom TAB does not activate ProtocolLib is required. Without it, the code falls back to classic mode.
interval-ticks below 20 does not feel faster in TAB The tab manager clamps it to a minimum of 20.
WorldGuard region condition never matches Make sure WorldGuard is installed and the region ID is exact.
PAPI conditions do nothing PlaceholderAPI must be installed, and the placeholder must return a value for that player.
Cross-server count looks right in classic TAB but not in custom TAB That is current code behavior. Custom layout does not use the full network placeholder resolver.
Simple bossbar and multi-bossbar overlap Disable the simple bossbar in settings.yml if you only want the multi system.
Regex world matching requested by a client Not supported in the current condition code. Only direct world-name equality exists today.
After changing these files, reload with /oer or /oereload.
For the most predictable setup today: use scoreboard.yml for the sidebar, tab.yml for TAB, and custom-nameplates/config.yml -> bossbars for modern bossbars.
